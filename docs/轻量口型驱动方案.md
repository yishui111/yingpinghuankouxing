# 轻量 3D 表情数字人方案（语音驱动 + 可换皮）

> 目标：替换现有 MuseTalk 的重方案（GPU + 16.9GB 镜像），实现一个**低配机器实时运行**的 3D 表情数字人：
> 一张可换皮的低面数 3D 模型 + 语音实时驱动**整个表情**（嘴型、眉毛、眼睛、嘴角、头部微动）。
> 核心原则：**不识别语音内容，只提取声学特征驱动表情**，因此模型通用——不挑人、不挑语言、不挑内容。

---

## 一、与旧方案的本质区别

| | MuseTalk（现状） | 本方案 |
|--|------------------|--------|
| 形态 | 视频口型合成 | **实时 3D 表情模型**（VTuber/动画人式） |
| 硬件 | 必须 NVIDIA GPU | **纯 CPU + 集成显卡即可实时** |
| 体积 | 16.9GB 镜像 | 网页版 **<20MB，零安装** |
| 模型 | 大模型全家桶 | **低面数 3D 模型 + blendshape，无神经网络推理** |
| 延迟 | 秒~分钟 | **实时（<50ms）** |
| 驱动 | 理解语音内容对齐口型 | **声学特征（能量/F0/语速）驱动表情**，不认内容 |
| 换皮 | 不支持 | **核心特性：贴图/资产与表情骨架分离，随时换皮** |

两者共存：本方案为默认轻量实时模式；MuseTalk 保留作高保真备用。

---

## 二、整体架构

```
音频（文件 / 麦克风）
   │ ① 声学特征提取（CPU 毫秒级）
   │    · RMS 能量 → 嘴部开合
   │    · F0 基频   → 眉毛/情绪
   │    · 语速/过零率 → 眨眼/头部微动
   │    · 兴奋度（能量+音调起伏）→ 微笑/眯眼
   ▼
表情参数集（blendshape 权重，约 10~20 个）
   │ ② 映射与平滑
   ▼
3D 模型实时渲染（低面数人头 + blendshape + 贴图）
   ├─ 网页版：Three.js（WebGL/WebGPU），浏览器即用
   └─ 桌面版（可选）：Electron / Godot / Unity 打包 exe
   │
   ▼
输出：实时预览 / 录屏导出 / 直播推流（后期）

换皮系统（随时可做）：
  模型几何 + blendshape 骨架  ←固定→  贴图/材质/头发/衣服（替换即换皮）
```

**关键点：全程无神经网络推理。** 每帧只有"算特征（几毫秒）+ 设 blendshape 权重 + GPU 画几千个三角面"，低配机器（4 核 CPU + 集成显卡）实时无压力。

## 三、3D 模型与"换皮"设计（重点）

### 3.1 资产结构（皮与骨分离）

```
avatar/                       ← 一个"可换皮角色" = 固定骨架 + 可换皮
├── base.glb                  ← 低面数人头模型（几何 + blendshape + 骨骼，固定）
├── skins/
│   ├── skin_default/         ← 默认皮
│   │   ├── albedo.png        ← 肤色/五官贴图（换皮=换这张图）
│   │   ├── hair.glb          ← 头发（可换模型）
│   │   ├── outfit.glb        ← 衣服/装饰（可换模型）
│   │   └── material.json     ← 材质参数（肤质、金属度等）
│   ├── skin_zhang3/          ← 皮2：张三点
│   └── skin_li4/             ← 皮3：李四点
└── 表情蓝图表情.json          ← blendshape 定义与语音映射参数（见第四节）
```

- **换皮 = 不碰 base.glb，只替换 skins/ 下的贴图和附加模型**，表情动画完全不受影响。
- 皮的数量不限，运行时下拉切换、热替换。

### 3.2 模型来源（三选一，由易到难）

| 来源 | 说明 | 成本 |
|------|------|------|
| **内置免费 CC0 人头**（推荐起步） | 用现成低面数人头（如 Ready Player Me、MakeHuman 导出的 glTF），自带 ARKit 风格 blendshape | 免费，当天跑通 |
| **你们自有的 3D 模型** | 若已有捏脸/模型资产，导出 glTF/GLB，按第三节规范接 blendshape | 需做一次适配 |
| **程序化参数化人头**（远期） | 用代码自动"捏"低面数人头（五官参数化），换皮=换参数 | 工作量大，后期再说 |

> 起步建议：内置免费低面数人头，这就是你说的"最简单的模型"；换皮贴图机制先跑通，后期换任何皮都行。

### 3.3 blendshape 表情集（ARS 子集，约 15 个）

只做一套覆盖主要表情的最小集（对应标准 ARKit 53 项的子集，绝大多数现成模型自带）：

| 类别 | blendshape | 驱动来源 |
|------|-----------|----------|
| 嘴部（主） | mouthOpen、mouthWide、mouthSmile、mouthFrown | 能量包络（见 4.1） |
| 眉毛 | browUpLeft/Right、browDownLeft/Right | F0 基频（见 4.2） |
| 眼睛 | eyeBlinkLeft/Right、eyeSquintLeft/Right | 语速/眨眼模型（见 4.3） |
| 辅助 | jawOpen、cheekPuff | 能量/随机抖动 |

> 后期想提升嘴型真实度，可扩展 mouthPucker（o 形）、mouthFunnel（u 形）等元音 blendshape（对应原方案的 L1 音素口型，另案）。

## 四、语音驱动表情算法（核心）

### 4.1 嘴部开合 ← 能量包络（主驱动）

```
1. 分帧：20ms 帧长、10ms 帧移
2. 每帧能量：E(t) = sqrt(mean(x²)) → 转 dB
3. 包络平滑：attack ≈ 10ms（快张）、release ≈ 200ms（缓闭）
4. 自适应归一化：滑动窗口（3s）95 分位作 E_max、-50dB 作 E_min
   → mouth = clamp((E_dB-E_min)/(E_max-E_min), 0, 1)
   （自适应后任何音量的音频，嘴型幅度都一致——"通用"的关键）
5. 静音门限：< -50dB → mouthOpen=0（闭嘴），表情整体归零
6. 自然感抖动：±3% 低频随机
7. mouthOpen 权重 = mouth（另按需给 mouthSmile 少量联动）
```

### 4.2 眉毛/情绪 ← F0 基频

- F0 提取用轻量算法（自相关/pYIN，CPU 毫秒级），**不需要**大模型；
- 映射：F0 相对本人均值升高 → browUp 权重增大（"惊讶/上扬"感）；F0 抖动剧烈 → browDown 微动（"激动"感）；
- 效果：说疑问句/情绪激动时眉毛会动，这正是"整个表情在变化"的观感来源。

### 4.3 眼睛/头部 ← 语速与说话状态

- 语速（短时过零率/能量变化率）升高 → 眨眼频率升高、头部轻微晃动幅度增大（说话点头感）；
- 眨眼模型：静音段正常眨眼（每 3~6s 一次）；说话段眨眼频率略升；
- 兴奋度 = 能量方差 + F0 方差 → eyeSquint、mouthSmile 联动（越兴奋越"眉开眼笑"）。

### 4.4 关于"声纹"的定位（沿用澄清）

- 声纹是"谁在说话"的身份特征，不直接产生表情；
- 控制表情的是上述**声学特征**（能量、音调、语速、兴奋度）；
- 声纹的正确用法（后期可选）：多说话人场景识别"当前是谁"，切换对应皮/表情风格。

## 五、实现方式与里程碑

### 技术栈

| 形态 | 技术 | 优点 | 缺点 |
|------|------|------|------|
| **网页版（推荐先做）** | Three.js + Web Audio API | 零安装、跨平台、低配可跑、换皮即改文件 | 高级渲染受浏览器限制 |
| 桌面版（后期可选） | Godot / Unity / Electron | 更复杂换皮、直播推流、性能上限更高 | 需打包安装 |

> 起步用网页版，功能验证后如需直播/复杂换皮再打包桌面版（资产与代码逻辑可复用 90%）。

### 里程碑

| 里程碑 | 内容 | 预估 |
|--------|------|------|
| **M1** | 网页版 MVP：内置低面数人头 + 上传音频/麦克风 → 能量包络实时驱动 mouthOpen → 实时预览 + 录屏导出 | 1~2 天 |
| **M2** | 表情扩展：F0 驱动眉毛、语速驱动眨眼/头部微动、静音闭嘴、抖动自然感 | 1~2 天 |
| **M3** | **换皮系统**：贴图/头发/衣服替换 UI + 热切换 + 换皮素材规范文档 | 1~2 天 |
| **M4（可选）** | 元音口型 blendshape（A/E/I/O/U）、API 接入现有网关、双模降级 | 按需 |

### 低配硬件基线（目标）

- 任意 4 核 CPU（含多年前的办公机）+ 集成显卡；
- 低面数模型（≤1 万三角面）+ 简单材质，网页 60fps 无压力；
- 内存 ≤2GB 占用；部署体积网页版 <20MB。

## 六、需要你确认的决策点

1. **模型来源**：内置免费低面数人头起步可以吗？还是你们已有现成 3D 模型/捏脸系统要接入？
2. **运行形态**：先做网页版（零安装、浏览器即用）可以吗？还是必须打包成桌面 exe（直播/推流用）？
3. **表情范围**：M1 只做"嘴部开合"，M2 加"眉毛/眼睛/头部微动"（整体表情变化）——这个节奏 OK 吗？
4. **换皮素材**：初期用"贴图替换"（换肤色/五官/头发图片）验证，够吗？还是需要完整的捏脸参数系统？

## 附录 A：照片 2D 方案（备选/最快验证原型）

若想先用最少的功夫验证"音量驱动嘴部"的效果（不建 3D 模型），可做浏览器版 2D 原型：
上传一张正脸照片 → MediaPipe 检测嘴部一次 → 能量包络驱动嘴部网格 2D 变形 → 实时预览。
一天内可出效果，用于验证驱动算法；验证后再迁移到 3D 模型（驱动算法部分完全复用）。

## 附录 B：为什么这个思路"够用"（原理依据）

- 人眼对"说话"的感知主要来自**口型与表情随时间的变化节奏**，而非口型细节；音量/音调包络与真实发音的开合、情绪高度相关。
- VTuber、皮套人、动画人直播早已验证：声学特征驱动 blendshape 是行业标准做法，效果被大众接受。
- 全程无神经网络推理，成本与硬件门槛极低，且模型通用（不认内容、不认人、不认语言）。
