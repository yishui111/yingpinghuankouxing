# 原部署笔记（历史文档）

> 本文是项目早期的部署笔记，保留作为参考；**最新、最完整的部署步骤以根目录
> `DEPLOY.md` 为准**（README 已指向该文件）。内容已脱敏，不再包含本机路径。

## 一、项目是什么

MuseTalk 数字人口型同步服务（Web 控制台 + API，端口 5000），镜像 + 代码按本仓库
布局组织，按 `DEPLOY.md` 操作即可在另一台电脑复原。

## 二、外部依赖（需每台电脑单独装）

| 依赖 | 用途 | 安装 |
|------|------|------|
| Docker Desktop（或 Linux/macOS 的 Docker Engine） | 运行容器 | https://www.docker.com |
| NVIDIA 显卡驱动 | GPU 推理（约 2.2GB 显存） | 官网驱动 |

## 三、部署要点

1. 拉取/复制本仓库到目标电脑。
2. 安装并启动 Docker Desktop（"Engine running"）。
3. 下载 `image.tar`（约 16.9GB）放入项目根目录。
4. 双击 `启动.bat`（或 `start.bat`）：
   - 检查 Docker
   - 若镜像 `musetalk-platform-full` 未加载，自动从 `image.tar` 导入（约 5-10 分钟）
   - `docker compose up -d` 启动容器
5. 等 1~2 分钟模型加载，验证：
   - 浏览器打开 http://localhost:5000 看到控制台
   - `状态.bat` 或 `curl http://localhost:5000/api/health` 返回 status=ok

## 四、日常操作

| 操作 | 命令 |
|------|------|
| 启动 | `启动.bat` / `docker compose up -d` |
| 停止 | `关闭.bat` / `docker compose stop` |
| 状态 | `状态.bat` |
| 日志 | `docker logs -f musetalk` |
| 清理重建 | `docker rm -f musetalk` 后再启动 |

## 五、数据都在哪

| 数据 | 位置 |
|------|------|
| 输入视频/音频 | `input\`（容器 /app/input） |
| 生成结果 | `output\`（容器 /app/outputs） |
| 模型/推理缓存 | `cache\`（HuggingFace / PyTorch / 预处理） |
| 业务数据 | `data\`（容器 /app/data，网页端「服务器文件」可点选） |
| 素材目录 | 可选：项目根目录 `materials\`（容器 /app/materials，见 docker-compose.yml 注释） |

> 说明：以上 `input/`、`output/`、`cache/`、`data/`、`materials/` 均被 .gitignore
> 忽略、不随仓库分发；首次 `docker compose up` 会自动创建空目录。

## 六、网络说明

- 容器名固定为 `musetalk`，加入（或自动创建）网络 `digital-human-net`。
- 若本机还有其他服务（如 API 网关）使用同名网络，可互相通过
  `http://musetalk:5000` 访问本服务。

## 七、故障排查

| 现象 | 处理 |
|------|------|
| 启动报 Docker 未运行 | 启动 Docker Desktop |
| 镜像加载失败 | 检查 image.tar 是否完整（约 16.9GB），重新 `docker load -i image.tar` |
| API 一直未就绪 | `docker logs -f musetalk` 看日志；可能是模型加载慢或显存不足 |
| 端口 5000 被占用 | 停掉占用程序 |
| 无 NVIDIA GPU | 服务要求 GPU；无 GPU 环境请勿使用（CPU 模式极慢，不建议） |

## 八、验证清单

- [ ] `docker ps` 里有 musetalk 容器且状态 Up
- [ ] http://localhost:5000 可打开控制台
- [ ] /api/health 返回 ok
